# 0030: Split the benchmark record out of README.md

## Status

Accepted

## Context

README.md had grown to 510 lines, roughly 52 KB. Four hundred of those lines — about 80% — were benchmarks: goache's own numbers, a cross-library comparison in eight categories at five working-set sizes, a core-count sweep, and the entire single-core analysis including a decomposition of where a `Get`'s 16.35 ns goes.

That is the direct result of two standing rules in this project working exactly as intended. Every benchmark table and fenced block needs a chart directly under it ([ADR 0024](0024-chart-per-benchmark-table.md)), and README's numbers must be refreshed whenever anything is re-measured. Nothing here was padding — each table earned its place by a rule, and the rules are right.

The problem is what the page became. A reader arriving at the repository wants to know what goache is, whether it fits, and how to call it. That is 110 lines. Everything after it is evidence, and evidence for a claim is not the same document as the claim. Someone auditing whether `WithMaxSize` eviction scales, and someone deciding whether to `go get` this at all, are not reading for the same thing and should not be handed the same page.

## Decision

`benchmarks/README.md` holds the complete record. Root `README.md` keeps the three comparisons that decide which cache to reach for, and links to the rest.

The three that stay were picked as the ones a reader needs before choosing, not the ones that look best:

| Table | Why it stays |
| --- | --- |
| Concurrent `Get` by core count | The answer changes with the CPU budget, and the crossover between one and two cores is the single most decision-relevant fact here. It is also the table where goache loses — at one core to go-cache by 45% |
| `NewSingleCore` against the whole field | The strongest claim in the project, and the caveats belong next to it |
| `ParallelGet` by working-set size | Where sharding pays, which is what `New` is for |

Each already had a chart, so the split needed no new chart definitions — the three cited by both pages are `compare-cpu.svg`, `singlecore-vs-field.svg` and `compare-parallel-get.svg`.

README goes from 510 lines to 176, and 52 KB to 15 KB.

### `benchmarks/` is documentation, `bench/` is code

These are two directories with confusingly similar names and it is worth being explicit about why both exist. `bench/` is a separate Go module holding the comparison benchmarks, kept apart so comparison-only dependencies never reach consumers of goache ([ADR 0008](0008-separate-comparison-bench-module.md)). `benchmarks/` contains one Markdown file and no code.

Merging them was considered and rejected: putting the prose in `bench/README.md` would mean the benchmark record for goache's *own* benchmarks (which live in the root module, not in `bench/`) sits inside a module that does not contain them. The naming collision is the smaller cost. Both directories now say what they are in their first lines.

### Rejected: keeping a summary table of everything in README

An obvious middle path is one condensed table with every category at a single size, so README still "has all the numbers". It fails the chart rule — no such chart exists and one would have to be invented for a table that exists only because it is small — and it fails the reader, since a single-size row hides exactly the size-dependence the full tables are for. `Bounded` at n=100,000 says nothing about `Bounded` at n=1,000, where the ranking inverts.

### Rejected: moving the charts too

`docs/img/` stays where it is. The charts are generated by `docs/benchcharts`, referenced from both pages, and moving them would mean either duplicating files or making one page reach into the other's directory. Relative paths from `benchmarks/README.md` (`../docs/img/…`) cost nothing.

## Consequences

- Root README is a page about the library again. The benchmark record is a page about the measurements, with its own table of contents and its own methodology section up front.
- **Three tables now exist in two places.** This is the real cost, and it is a drift risk of exactly the kind [ADR 0027](0027-single-core-field-claim.md) had to clean up. CLAUDE.md's performance policy now names the three and requires both pages to change together.
- The measurement-discipline rules that were previously only in CLAUDE.md and ADR 0027 are now stated at the top of `benchmarks/README.md`, where someone reading the numbers will actually see them.
- `docs/benchcharts/main.go`'s comments referenced "README.md" section-by-section for every chart; they now name whichever page holds each. The generator itself is unchanged and produces byte-identical SVGs.
- Anchor links in README that pointed at the single-core section (`#single-core-mode-newsinglecore`) now point across to `benchmarks/README.md`. There is no tooling that checks these — a moved heading breaks them silently.
